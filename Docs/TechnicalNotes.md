# Garden Snake — technical notes

## Stack and assets

- Unity 6000.6.0f1, C#, Universal Render Pipeline, Unity Input System, uGUI / TextMeshPro, and Unity Test Framework.
- Unity Pipeline is installed as an Editor automation tool. The game code has no dependency on its APIs.
- [Feel](https://feel.moremountains.com/) (MMFeedbacks + MMTools) provides the reaction layer: camera shake, freeze frames, timescale, screen flash, particle emission and UI springs. The players are authored from code by `GardenFeel`, so a scene rebuild reproduces them exactly.
- [All In 1 Sprite Shader](https://assetstore.unity.com/packages/vfx/shaders/all-in-1-sprite-shader-156513) draws the two flat quads that should read as light rather than geometry: the apple's ground pool and the shockwave ring a pickup throws out. Both use its glow pass so they interact with scene bloom.
- All twenty 3D assets were generated in Blender 3.5 with the included Python source: snake head, body, tail, apple, garden tile, planter, flower, rock, two rounded rim lengths, gnome, tree, bush, watering can, spade, rake, flowerpot, tulip, lavender, and daisy. The `.blend` file is editable and FBX exports are committed project assets.
- Materials, lighting, post-processing, scene layout, and particle effects are authored by the Unity scene builder. No stock model pack or image-generation service is used.
- Every UI shape — rounded panels, the pill, circles, the pause/play/sound glyphs, the soft mote, the ring and the lawn gradient — is described as a signed distance field in `GardenSprites` and rasterised straight into a PNG asset. No UI art is imported.
- Seven sounds are original mathematical synthesis, generated by `Tools/generate_audio.py`: turn, pickup, start, new best, click, loss, and a 16-second ambient bed. The bed's partials and envelopes are snapped to whole cycles per loop and its filter is warmed over a previous pass, so it repeats without an audible seam. No sampled recordings or third-party audio pack is used.
- Liberation Sans is distributed with Unity's TMP Essential Resources and used under the included SIL Open Font License. TMP shader sources come from that same installed uGUI package. `Tools/extract_tmp_resources.py` records the extraction process. Unity generates the TMP settings and font atlas; no serialized asset YAML is handwritten.
- Existing project/template files and packages remain in place.

## Implementation decisions

The simulation uses integer grid cells with a fixed gameplay tick. Rendering interpolates between previous and current cells each frame. This keeps collisions deterministic while movement looks smooth. Input stores up to two turns and validates each against the last queued heading, preventing both reversal and accidental dropped corners.

Food is selected uniformly from free cells with a bounded scan. It never uses an unbounded random retry loop, including near a full board. The tail's previous cell is legal to enter on a non-growth tick. Filling every cell produces a win state instead of attempting another food spawn.

The board is 21 x 12 rather than square, so a widescreen window is filled by the garden instead of by two empty gutters. The camera fits the board between two HUD bands from the board's own corners, which means the score, wordmark and buttons never sit on top of the field at any aspect ratio, and it eases between a resting framing on the menus and a closer one during a run.

Presentation stays separate from the simulation. `SnakeFeel` is the only seam: the controller reports that an apple was eaten and how long the run is, and the Feel players decide how loud that looks. Everything else — the slither wave, the growth pulse, the head banking into a turn, the apple's drop-in, the death pop — is timing and motion in `SnakeController`, with all of it serialized for tuning.

Allocation is kept out of the run loop. Every body segment a full board could ever need is instantiated once during `Awake` and toggled with `SetActive`, so eating an apple never triggers an `Instantiate` on the frame it lands. The read-only body is walked by index rather than `foreach`, which would box its enumerator every tick, and the score and best labels reuse pre-rendered numerals. No physics colliders are needed for grid rules.

The web template includes loading progress, a keyboard focus target, capped pixel density, and a load-error display. Local best score and mute preference use PlayerPrefs; there is no backend, login, analytics, or network gameplay. Uncompressed WebGL output favors straightforward hosting over download size.

## Verification

Existing Edit mode tests remain in the repository. Current verification uses Play Mode runs and captured frames; do not add or run unit tests unless explicitly requested. `GardenPlaythrough` drives the real controls in Play mode and checks the whole flow. `GardenPlaytest` plus `Tools/Harness/gs.py` add an unattended autopilot: it enters Play mode from a terminal, steers with real Input System events, restarts after each death, and writes a screenshot filmstrip that can be reviewed frame by frame. That loop is how the visual pass in this repository was iterated.

## Polish controls

`SpeedGauge` draws a layered speedometer directly as a uGUI mesh. The needle follows the actual step interval with a damped spring; each speed gain pulses the housing. The numeric readout is cells per second and the caption reaches ?ZOOMIES!? at the speed cap. No extra sprite dependencies are required.

`RunRecord` snapshots the previous best at the start of each run. Tying it stays quiet. Passing it triggers one large celebration; each subsequent apple gets a smaller toast, a best-label pulse, six extra particles, and a quiet chime. The first-ever run suppresses both record effects. `GardenSnake.HasPlayed` persists this distinction, including a previous run that scored zero. Existing nonzero best scores count as a previous run.

`GridCellWaves` controls all 252 tile heights without changing grid coordinates. Its serialized presets expose amplitude, propagation speed, duration, and width. `Play(pattern, sourceCell)` accepts any source cell; `Play(preset, sourceCell)` accepts custom settings. Ripple, Bloom, Sweep, and CheckerHop are included. Starts use Sweep, record crossings use Bloom, milestones use CheckerHop, and collisions use Ripple. Multiple sources overlap in a bounded eight-wave buffer with a 0.48-unit height ceiling. Snake segments and apples follow the sampled surface height; pause freezes the wave and restart clears it. A 50 ms visual timestep cap preserves the source beat after a stalled frame. Play Mode context menus preview the presets.

`GardenDecor` authors the garden vignettes and seamless 128-pixel grass/clay maps. Large props sit outside the board; the snake uses low-resolution smooth spheres, asymmetric eyes, cheeks, freckles, teeth, and a tongue. Rebuild through `GardenBuilder` to reproduce the complete scene. The builder refuses to overwrite an open dirty scene.

`Tools/Harness/polish_play.cs` observes record counts while the real keyboard autopilot collects apples. `polish_waves.cs` captures all four wave presets and an overlapping-source stress case, checking bounded heights, propagation, settled positions, and unchanged simulation coordinates. Run these through `unity command eval_file` in Play Mode from Ready. Record scenarios require a temporary best/has-played fixture; back up and restore those PlayerPrefs after stopping Play Mode. Captures and reports go to `Artifacts/`.
