# Technical Notes | Ori Ben Nun | PiKoYa Game Developer Assignment

## Stack & Assets

Unity 6000.6.0f1, URP 17.7, C#. WebGL build, hosted on itch.io.

Third-party plugins: Feel (MMFeedbacks + MMTools) by More Mountains, used for the reaction (feedback) layer.

Visual assets are all generated by tools written by AI (mainly Codex Astra Hight):

- The 3D models were authored in Blender through Python scripts and exported as FBXs directly into Unity
- All UI assets were generated mathematically (SDFs) and baked into PNGs under `Assets/UI/Generated`.
- The grass and clay maps are small seamless textures generated the same way.

Audio:
The six sound effects (turn, pickup, start, new best, click, lose) are synthesised by AI generated tool `Tools/generate_audio.py`.
The background music is the one asset I did not make: a free loop from Freesound.org, "Pawsome Vibes" by Kjartan Abel [https://freesound.org/people/kjartan_abel/sounds/679355/]

## AI Usage

I used AI across most of the project. The full record is in [`Docs/AI Usage Documentation.md`]: every prompt in order, with my steering and the reasoning behind the corrections. Feel free to read it to see the full context and workflow.

Mainly using two agents, alternating and occasionally running in parallel:

- **OpenAI Codex (GPT-6 "Astra", Medium/High) - The heavylifting.**. First pass and most of the content work: grid simulation and game loop, input, initial scene, the Blender generation scripts and the later model sweeps, audio synthesis, WebGL template, speed gauge, board wave system, and the garden environment.
- **Claude Code (Opus 5 High) - The iterative workhorse.** Visual and feel sweeps plus the structural work: UI and HUD, Feel integration, pooling and allocation fixes, the snake's mouth and expression, the refactor into four assemblies, the ScriptableObject tuning layer, and the final cleanup passes.

The vast majority of the C# was written by AI. The same applies to the assets that come out of scripts: the Blender geometry, the procedural UI sprites, and the sound effects. No image-generation service was used, and there is no "AI-generated art" in the build.

Workflow: I ran the agents in a verification loop rather than task by task: play in the Editor, capture frames, list what is wrong, implement, verify, commit, repeat. That required a harness (`Tools/Harness/gs.py`) that drives the live Editor from a terminal using the new Unity CLI tools (and my own custom agent skills around that workflow).

I steered throughout, mostly from looking at the live code/UYML changes made by the AI. The design, feel and architecture is mine. I specified the four-layer split and the downward data flow, then corrected the result where it drifted toward patterns that do not belong in a Unity project (IMO). The same applies to the tuning layout, the `Cell` struct over `Vector2Int`, and deciding which values stay constants because changing them would break the scene.

Between AI sessions I did manual passes myself: scene and prefab work, code review, cleanup, and playtesting every build.
